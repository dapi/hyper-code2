## Decision question

Which versioned discovery/retention contract lets agents reliably create, find,
understand and reuse ordinary callable capabilities without sacrificing free
function composition or inventing a universal promotion lifecycle?

## Why a new cycle

R-001 is terminal `inconclusive`. Two passes of the first task family did not
confirm retention/reuse, but the evidence covers one task and one model alias.
The remaining old fixtures must not run under the unchanged contract. R-014 is
also inconclusive because candidate surfaces had paper descriptions rather than
symmetric runtime evidence.

## Comparative scope

Use the same disposable fixtures and call budget to compare versioned contracts,
not production architectures:

1. current ordinary `ctx.fns` discovery with corrected explicit retention
   instructions;
2. a read-only capability manifest/catalog projection over ordinary functions;
3. generated signature/type projection;
4. a bounded descriptor-mediated prototype, only as a disposable comparison.

Every variant must preserve ordinary callable composition, explicit save/review,
fresh-process reuse, exact golden output and honest failure reporting.

## Required evidence

- frozen prompts/contracts, fixtures, model alias and runner versions;
- symmetric runtime implementations or disposable projections for each variant;
- exact correctness, discovery steps, calls/tokens, retained artifact, control
  call, fresh-process reuse and false-success checks;
- compatibility and authority implications separated from product correctness;
- explicit limitations and an ADR trigger if a global runtime surface is selected.

## Boundaries

- Research & Discovery Flow; no production feature is implied.
- No real secrets, public HTTP, shared state or production migration.
- Do not run the two old R-001 families unchanged.
- Do not require every useful one-off composition to become a saved capability.
- Do not select mediation merely because issues #14/#16 describe it in detail.

Decision owner: Danil Pismenny.

Stopping condition: symmetric evidence supports one contract, rejects all tested
contracts, or remains insufficient under the fixed time/call budget.
