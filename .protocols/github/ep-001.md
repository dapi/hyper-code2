## Outcome

Produce evidence for `VAL-01…VAL-05` before selecting a broad runtime
architecture. The first wave uses the existing browser/runtime and tests whether
ordinary functions can be found, composed, retained explicitly and used in later
relevant work.

## Current roadmap

1. Establish the representative-task experiment contract and baseline.
2. Run the current-runtime reuse experiment.
3. In parallel, split active fork/identity debt and research the network and
   secret boundaries.
4. Make conditional architecture dispositions from evidence.

## Boundaries

- TUI is a separate supporting stream and is not a prerequisite.
- Multi-user, reflection/consolidation and adversarial sandbox delivery are not
  part of this epic.
- Do not impose a universal `discover -> compose -> save -> verify -> reuse` lifecycle.
- Run experiments only in trusted local workspaces, without HTTP exposure and
  without real secrets; controlled sentinels are allowed.
- Existing issue bodies are design inventory, not approved architecture.

## Stop rule

Do not expand mediated runtime, journal, compact-result, approval or UI work
until the relevant experiment or security decision shows that mechanism is needed.

## Completion

- `VAL-01…VAL-05` receive supported, unsupported or inconclusive verdicts with limitations.
- Fork, network-authority and secret gaps have bounded owner issues.
- Any selected project-wide architecture has evidence and an accepted ADR.
- Legacy epic #10 is explicitly superseded after useful outcomes are transferred.
