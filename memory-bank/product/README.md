# Product Documentation

Product documentation explains why hyper-code2 exists, for whom, and what
observable outcomes matter. It does not own runtime implementation, protocol
syntax, database schema, or delivery sequencing.

- [Product context](context.md) — product promise, core workflows, constraints,
  rationale, and primary-source provenance.
- [Vision](vision.md) — durable direction, experience principles, and non-goals.
- [Customers and users](customers.md) — confirmed developer/operator/agent actors
  and explicit evidence gaps.
- [Metrics](metrics.md) — current measurement gaps and available engineering signals.
- [Marketing and positioning](marketing.md) — supported positioning claims and unknowns.
- [Roadmap](roadmap.md) — approved roadmap state and the boundary with TODO/design notes.
- [Primary product sources](sources/README.md) — source talks and other primary
  material explaining the product's origin and rationale; use for provenance,
  not instead of current implementation or canonical product documents.

Observable project-level scenarios are owned by the
[use-case registry](../use-cases/README.md).
